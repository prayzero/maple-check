## 실제 옵션 API 대조

조회 주소: [넥슨 공식 확률 검색 API](https://maplestory.nexon.com/Guide/OtherProbability/cube/GetSearchProbList)

- POST 인자: `nCubeItemID`(일반 `5062010`, 에디셔널 `5062500`), `nGrade`, `nPartsType`, `nReqLev`.
- 저장된 916개 맥락 전부와 120/201 대표레벨의 모든 등급·부위 조합을 합쳐 **980회 조회**했습니다.
- **916개**에서 3줄 확률표를 확인했습니다. 나머지 **64개**는 공식 응답의 ‘해당 장비 없음’ 결과이며 기존 데이터 삭제는 없었습니다.
- 표의 옵션 문구·순서 및 확률을 비교한 결과 **766개 동일**, **150개는 저레벨 기존 표와 소수 정밀도 차이**가 있었습니다. 부동소수점 직렬화 오차는 `1e-12` 허용오차로 구분했습니다.
- 차이가 있는 항목은 300개이며, 최대 차이는 확률 단위 `2.384e-9`입니다. 예: 일반 잠재 레전드리 20레벨 모자의 둘째 줄 `올스탯 +3%`가 기존 2%에서 공식 표시 2.0000002384%로 정밀해졌습니다. **이 차이를 새로운 게임 확률 개편으로 단정하지 않습니다.**
- 120/201 대표레벨의 기존 256개 맥락은 기존 표와 일치했습니다.
- 기존 저레벨 660개 맥락에 공식 표의 현재등급/하위등급 구분을 명시적으로 추가했습니다. 이전 문구 기반 추론과 이번 실제 등급 구분의 불일치는 없었습니다.
- 재생성 결과: 옵션 406개, 분포 428개, 맥락 916개. 모든 2,748줄에 명시적인 등급 출처가 있습니다.

수집된 맥락별 `[옵션 문구, 표시확률, 현재등급 여부]`를 UTF-8 압축 JSON으로 직렬화해 각각 SHA-256을 구하고, 키 정렬된 해시 맵의 SHA-256을 계산했습니다:

`65e77564fbd1b3aa8b6d34a79fae264c06a6e3bad781c4d98748f5c8dc30e870`

이 값과 조회/유효 맥락 수를 `cube-options-v2.json`의 `meta.verification`에 저장했습니다. 수집일은 실제 전체 조회가 성공한 뒤 갱신했습니다.

## 수정한 계산·수집 문제

1. **천장 이상 실패 입력 시 무료 등급업으로 계산되는 문제:** 일반 레어→에픽 실패 10회 입력 시 기존 결과가 0회·0메소였습니다. 이미 보장 횟수에 도달한 실패 기록은 정상적인 상태가 아니므로, 연속 실패를 0부터 보장 횟수−1까지만 받게 했습니다. 마지막 보장 시도의 메소는 반드시 포함됩니다. 일반↔에디셔널 전환 시에도 현재 방식의 범위로 보정합니다.
2. **아무 옵션이나 허용해도 100%가 아닌 문제:** 무기 200레벨에서 세 줄 모두 ‘아무거나’일 때 기존 확률은 약 0.9999934000116132였습니다. 공식 표의 반올림 누적 오차였습니다. 모든 결과를 허용하는 목표는 정확히 1로, 나머지 결과는 0~1 범위로 제한했습니다.
3. **오래된 저레벨 표에 새 수집일을 붙일 수 있는 빌더:** 기존 빌더는 고레벨만 다시 읽고 저레벨은 유지했습니다. 이제 기존 맥락도 모두 재조회합니다. 잘못된 HTML·불완전한 표는 실패로 처리하고 공식 ‘장비 없음’ 응답만 빈 결과로 인정합니다.
4. **표시 기준 불명확:** 메소 재설정, 이벤트 미적용, 유니크→레전드리 연속 실패 0회 기준을 표시했습니다. 공식 출처 링크, 규칙 대조일, 옵션표 수집일을 분리했습니다. 250레벨 초과 입력은 공식 검색 범위 밖의 확장 근사값이라고 표시합니다.

## 검증 및 재현

실행해 통과한 명령:

```text
node tools/test_potential_official.js
node tools/test_core.js
node tools/test_equipment_budget.js
git diff --check
```

신규 테스트는 공식 등급업·비용 표, 독립적인 생존확률 합산으로 구한 천장 기대횟수, 마지막 유료 시도, 2,748개 줄의 확률 합·등급별 확률 질량, 저레벨 정밀도, 무조건/불가능 목표를 확인합니다. 빌더의 공식 빈 응답·잘못된 HTML 처리 및 부동소수점 비교도 별도 Python 검사로 통과했습니다.

전체 수집을 재현할 때:

```text
python tools/build_cube_options.py --report potential-audit.json
```

파일을 변경하지 않고 현재 공식 응답과 비교할 때:

```text
python tools/build_cube_options.py --verify-only --report potential-audit.json
```

기본 날짜는 한국 시간입니다. `--verified-on`은 실제 검증 날짜를 명시할 때만 사용합니다. 보고서의 `changed`는 옵션·표시확률 차이이며 `provenanceRefreshed`는 누락된 등급 출처 보강이므로 서로 겹칠 수 있습니다.

## 남은 모델 범위

- 공식 공개 표의 반올림된 확률을 사용합니다. 내부 원확률과 완전히 동일한 값이라고 주장하지 않습니다.
- 이전과 완전히 동일한 결과를 배제하는 내부 재추첨은 모델에 포함하지 않습니다. 현재 세 줄을 입력받지 않으므로 정확한 조건부 기대비용은 계산할 수 없습니다.
- 미라클 타임, 프라임 큐브의 첫째 줄 고정, 소울 잠재능력, 펄스 인핸서, 큐브 아이템 구매비는 포함하지 않습니다.
- 기존 요구사항에 따라 유니크→레전드리의 연속 실패 누적 입력은 지원하지 않고 0회 기준을 유지합니다.
- 공식 옵션 검색 UI 범위는 0~250레벨입니다. 계산기의 251~300 입력은 201~250 옵션표를 확장 적용하며, 해당 레벨에 실제 장비가 존재하거나 공식 옵션표가 검증됐다는 의미가 아닙니다.
- 120 미만 레벨의 레어·에픽·유니크 맥락은 기존 데이터 범위 밖입니다. 새로 만들어 추정하지 않았으며, 해당 예산 목표 계산은 공식 표 부재로 처리됩니다.
